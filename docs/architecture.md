# 아키텍처 초안

## 1. 레이어 구성

- `core`: 설정, 로깅, 공통 유틸
- `clients`: 한국투자증권 API HTTP 클라이언트
- `services`: 비즈니스 유스케이스 (시세조회, 주문, 포지션)
- `strategies`: 매매전략(신호 생성)
- `execution`: 주문 라우팅/리스크 검증/체결 추적
- `storage`: 거래기록, 상태 저장(초기에는 파일, 이후 DB)

## 2. 핵심 모듈

1. **AuthManager**
   - 액세스 토큰 발급/갱신
   - 만료 시간 캐싱
2. **MarketDataService**
   - 실시간/지연 시세 조회
   - 전략 입력용 데이터 정규화
3. **OrderService**
   - 주문 생성/정정/취소
   - 주문 전 리스크 한도 확인
4. **RiskManager**
   - 1회 주문 한도
   - 일일 손실 제한
   - 종목 집중도 제한
5. **StrategyEngine**
   - 전략별 시그널 계산
   - 동일 인터페이스(입력: 시장데이터, 출력: 주문의도)

## 3. 실행 시나리오

1. 스케줄러가 주기적으로 시세 조회
2. 전략 엔진이 매수/매도 시그널 산출
3. 리스크 매니저가 주문 가능 여부 검증
4. 주문 서비스가 API 호출
5. 결과를 로그/저장소에 기록

## 4. 품질 게이트

- 단위 테스트: 전략, 리스크, 파서
- 통합 테스트: API 모의 응답 기반 주문 플로우
- 운영 안전장치:
  - 모의투자 환경 우선
  - kill-switch 플래그
  - 거래 시간 제한
